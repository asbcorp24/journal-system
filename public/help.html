Полный хелп по созданию шаблонов и работе в системе

Этот документ описывает текущую логику системы полностью: как проектировать шаблоны справочников, шаблоны журналов, шаблоны печати и отчёты, как правильно связывать их между собой, как использовать формулы, SQL, скрытые поля, QR/штрихкоды, вкладки, импорт, экспорт и персональные доступы.

Кому подходит
Суперадмину, админу, мастеру, пользователю
Главная идея
Сначала шаблоны, потом данные, потом печать и отчёты
Что важно
Хорошая структура полей экономит много времени дальше

1. С чего начать

Правильный порядок настройки системы почти всегда одинаковый. Если идти в другом порядке, дальше начинаются лишние переделки.

  1. Создайте подразделения и настройте родительские связи.
  2. Создайте пользователей и назначьте роли.
  3. Создайте шаблоны справочников.
  4. Заполните справочники значениями.
  5. Создайте шаблоны журналов, используя готовые справочники.
  6. Проверьте ввод записей в журнале на тестовых данных.
  7. После этого добавляйте шаблоны печати и отчёты.
Если журнал использует справочник, этот справочник лучше продумать и заполнить заранее. Тогда в журнале не придётся потом менять структуру полей.

2. Роли и доступы

Суперадмин

Имеет доступ ко всей системе, всем подразделениям, всем журналам, справочникам, отчётам, экспорту базы, импорту базы, SQL-разделу и глобальным настройкам.

Админ

Работает в своём дереве подразделений. Может получать доступ к редактированию значений, к журналам, к отчётам. При отдельной галочке может редактировать свои шаблоны справочников и свои шаблоны журналов.

Foreman

Может работать с доступными журналами, а также добавлять и редактировать значения справочников, если у него есть доступ к ним. Удаление значений обычно оставлено администратору.

Worker

Обычно только заполняет доступные журналы и использует уже подготовленные справочники.

Важная логика доступа: админ родительского подразделения видит журналы и справочники дочерних подразделений.

3. Шаблоны справочников

Шаблон справочника определяет, какие поля будут у каждой записи справочника. После создания шаблона значения справочника хранятся в JSON, а отображаемое значение собирается из данных записи.

3.1. Где создаются

Суперадмин создаёт шаблоны в разделе Шаблоны справочников. Админ с разрешением на свои шаблоны работает в отдельной своей версии этого раздела и может редактировать только созданные им шаблоны.

3.2. Общие поля шаблона справочника

Поле Что означает
Название Человеческое имя справочника. Например: Номенклатура, Цехи, Поставщики.
Код Короткий системный код. Желательно уникальный и понятный. Например: nomenclature.
Описание Свободная подсказка для администратора и пользователя.
Подразделения К каким подразделениям относится справочник.
Автор Кто создал шаблон. Это отображается в списке шаблонов.

3.3. Поля внутри записи справочника

У каждой записи можно создавать следующие типы полей:

Тип поля Для чего нужен Пример
text Обычный текст Название, марка, описание
number Число Вес, цена, длина
date Дата Дата выпуска, дата закупки
time Время Время приёмки
list Список фиксированных вариантов Статус: новый / в работе / списан
qr QR или штрихкод Инвентарный код, бирка детали
directory Ссылка на другой справочник Категория, поставщик, цех, место хранения
calc Вычисляемое поле по формуле price * quantity

3.4. Настройки каждого поля

  • Ключ поля нужен для хранения и формул. Пишите только латиницей: name, part_number, weight.
  • Название поля видит пользователь.
  • Вкладка группирует поля по вкладкам в форме добавления и редактирования.
  • Обязательное запрещает сохранять запись без значения.
  • Уникальное не даёт сохранить вторую запись с тем же значением в этом поле.

3.5. Поле типа список

Для list перечислите варианты. Один вариант на одно значение логики. Не делайте слишком длинные и размытые формулировки. 

Тип:
list

Варианты:
новый
в работе
списан

3.6. Поле типа QR/штрихкод

  • Можно разрешить ручной ввод.
  • Можно включить автогенерацию.
  • Если в справочнике есть хотя бы одно поле qr, система может искать запись по этому значению.
  • Штрихкоды можно печатать отдельно вместе с названиями записей.

3.7. Поле типа справочник

Это ссылка на другой справочник. Например, у номенклатуры можно выбрать справочник Единицы измерения, Поставщики, Категории.

  • Нужно выбрать, на какой справочник идёт ссылка.
  • Форма умеет рекурсивно добавлять вложенные значения через кнопку +.
  • Можно строить цепочки хоть в несколько уровней: справочник в справочнике, внутри него ещё один справочник и так далее.
При экспорте значений справочника связанное поле теперь выгружается в двух видах: исходный id и отдельное поле _display с человекочитаемым текстом.

3.8. Поле типа формула

Формула нужна, если значение должно считаться автоматически по другим полям этой же записи. 

price * quantity
(width + height) / 2
length * width * height
  • В формуле используйте ключи других полей.
  • Лучше использовать только числовые поля.
  • Результат сохраняется как вычисленное значение и руками не редактируется.

3.9. Отображаемое значение записи

Система старается показать первое подходящее заполненное поле записи как главное отображаемое значение. Поэтому в большинстве справочников первым лучше ставить поле name или аналогичное.

3.10. Когда нельзя менять или удалять шаблон справочника

  • Если справочник уже заполнен значениями, его шаблон менять нельзя.
  • Если справочник уже заполнен, удалить его тоже нельзя.
  • Это сделано специально, чтобы не ломать данные.

4. Шаблоны журналов

Шаблон журнала определяет структуру записей, фильтры, скрытые поля, вычисления, работу со справочниками и поведение формы ввода.

4.1. Общие поля шаблона журнала

  • Название журнала — например, Поступление на склад.
  • Код — короткий системный код.
  • Описание — пояснение для пользователей.
  • Подразделения — кто работает с этим журналом.
  • Автор — кто создал шаблон.

4.2. Типы полей журнала

Тип Назначение
text Текст, комментарий, обозначение
number Количество, цена, длина, остаток
date Дата события. При добавлении по умолчанию подставляется сегодняшняя дата.
time Время события
list Фиксированный набор вариантов
directory Ссылка на справочник с хранением ID выбранного значения
directory_text Обычно используется, когда нужен текст из связанного справочника для отображения или печати
sql Поле, значение которого можно получить SQL-запросом
calc Вычисление по другим полям журнала
hidden Скрытое поле с значением по умолчанию, которое пользователь не видит при вводе

4.3. Что важно для каждого поля журнала

  • Ключ нужен для хранения, SQL и формул.
  • Название видит пользователь.
  • Вкладка группирует поля формы на отдельные вкладки.
  • Обязательное делает поле обязательным.
  • Фильтр добавляет поле в фильтры журнала на экране просмотра.

4.4. Поле журнала типа справочник

  • Нужно выбрать справочник.
  • Нужно выбрать, какое поле этого справочника показывать пользователю в выпадающем списке.
  • Даже если показывается не QR-поле, поиск по QR всё равно работает, если QR есть внутри записи справочника.
  • Рядом с таким полем может быть кнопка добавления значения справочника и кнопка сканирования QR/штрихкода.

4.5. Поле SQL

Поле SQL нужно, когда значение берётся из базы по запросу. Ожидается, что запрос возвращает одно поле и одно вычисленное значение.

  • Если в записи уже есть сохранённое значение этого поля, повторный автоматический расчёт не делается.
  • Для пересчёта есть отдельная кнопка Пересчитать.
  • Используйте такие поля осторожно: запрос должен быть понятным и быстрым.
Пример идеи:
поле: stock_left
логика: получить остаток по выбранной номенклатуре

4.6. Поле hidden

Скрытые поля не показываются пользователю в форме ввода, но сохраняются в записи. Это удобно для технических признаков, служебных значений, источника записи, кода процесса, статуса по умолчанию и похожих задач.

4.7. Ограничения числовых полей

Для числовых полей можно задавать сравнения:

  • не меньше числа;
  • не больше числа;
  • больше другого поля;
  • меньше другого поля.

Сравнение можно делать не только с другим числовым полем, но и с полем, которое приходит из справочника или из SQL, если на выходе там тоже число.

4.8. Когда нельзя менять или удалять шаблон журнала

  • Если в журнале уже есть записи, редактировать его шаблон нельзя.
  • Если в журнале уже есть записи, удалить журнал тоже нельзя.

5. Шаблоны печати журналов

Шаблоны печати нужны, когда обычной табличной печати мало и нужен оформленный документ: акт, маршрутный лист, сводка, накладная, ведомость и так далее.

5.1. Как это работает

  • Для журнала создаётся один или несколько шаблонов печати.
  • Пользователь открывает журнал, нажимает печать и выбирает нужный шаблон.
  • Фильтры текущего экрана учитываются при печати.

5.2. Что можно вставлять в шаблон

  • HTML-разметку: заголовки, таблицы, абзацы, подписи, блоки.
  • Поля журнала через шаблонные переменные.
  • Всю таблицу журнала одной вставкой.
{{ journal.name }}
{{ print.date }}
{{ table }}

5.3. Если HTML-шаблон пустой

Тогда система может использовать обычную табличную печать.

5.4. Подход к созданию шаблона печати

  1. Определите, печатается одна запись или сразу весь журнал по фильтрам.
  2. Решите, нужен ли чистый HTML-шаблон или достаточно таблицы.
  3. Добавьте заголовок, дату, подписи и таблицу.
  4. Проверьте печать на пустых и на заполненных данных.

6. Шаблоны отчётов

Отчёт — это отдельный шаблон, который пользователь выбирает и запускает. Он может строиться вручную через SQL или автоматически через конструктор типовых отчётов.

6.1. Кто создаёт

  • Суперадмин создаёт любые отчёты.
  • Админ с разрешением на свои шаблоны может создавать свои отчёты в доступных пределах.
  • Пользователь отчёт не конструирует, а только запускает, если ему дан доступ.

6.2. Варианты построения отчётов

SQL-отчёт

Полный контроль над выборкой. Подходит для сложных остатков, сводок, объединений, сравнений и расчётов.

Быстрый конструктор

Удобен для типовых отчётов по одному журналу без ручного написания SQL.

6.3. Параметры отчёта

Параметры — это поля, которые пользователь заполняет перед запуском отчёта. Они могут быть текстовыми, числовыми, датами, списками и справочниками.

6.4. Что важно при проектировании отчёта

  • Сразу продумайте, по каким полям пользователь реально будет фильтровать данные.
  • Если отчёт нужен многим, делайте параметры простыми и понятными.
  • Если отчёт можно собрать без SQL, лучше сначала попробовать конструктор.
  • Если отчёт должен печататься, заранее проверьте ширину колонок и названия столбцов.

6.5. Печать и экспорт отчётов

Пользователь может запускать доступный ему отчёт, просматривать результат и печатать его. Также в системе есть настройка персональных доступов к отчётам.

6.6. Импорт и экспорт шаблонов отчётов

Шаблоны отчётов можно выгружать и загружать обратно. Это удобно для переноса между базами, резервного хранения типовых шаблонов и клонирования сложных отчётов.

7. Значения справочников

7.1. Кто может работать со значениями

  • Foreman и admin могут добавлять значения в доступные им справочники из раздела справочников.
  • Admin может удалять значения.
  • Foreman и admin могут редактировать значения.

7.2. Как добавлять значения

  • Через раздел Справочники.
  • Прямо из журнала, если поле журнала ссылается на справочник.
  • Через вложенный рекурсивный +, если внутри записи есть ещё один связанный справочник.

7.3. Уникальность

Если в шаблоне поля стоит галочка Уникальное, система не даст сохранить вторую запись с тем же значением. Это работает и при добавлении, и при редактировании.

7.4. Импорт и экспорт значений

  • Поддерживаются форматы CSV и XML.
  • Перед массовым импортом удобно сначала сделать экспорт и взять его как образец.
  • Для связанных полей выгружаются и системные значения, и человекочитаемое отображение.

7.5. Печать справочников и штрихкодов

  • Можно печатать весь справочник.
  • Можно печатать отдельные QR/штрихкоды вместе с названиями.
  • Печать доступна не только суперадмину, но и пользователям, у которых есть доступ к справочнику.

8. Работа с журналами

8.1. Что хранится в записи журнала

  • Значения всех полей шаблона.
  • Кто добавил запись.
  • Кто проверил запись.
  • Комментарии и история проверки.
  • Статус записи.

8.2. Удаление и восстановление

В журналах используется soft delete: запись не исчезает физически, а помечается как удалённая. Администратор может включить показ удалённых записей и восстановить их кнопкой Восстановить.

8.3. Фильтры журнала

  • Фильтры по полям показываются только для тех полей, где в шаблоне включена галочка Фильтр.
  • Есть общий поиск, фильтры по датам, статусу, подразделению и удалённым записям.

8.4. Поля даты по умолчанию

При добавлении записи в поле типа date по умолчанию подставляется сегодняшняя дата.

8.5. Сохранение и закрытие

В форме записи есть две логики:

  • Сохранить — сохраняет запись, но не закрывает модальное окно.
  • Сохранить и закрыть — сохраняет и закрывает форму.

9. Импорт и экспорт

9.1. Что можно импортировать и экспортировать

  • значения справочников;
  • записи журналов;
  • шаблоны справочников;
  • шаблоны журналов;
  • шаблоны отчётов;
  • шаблоны печати журналов;
  • для суперадмина — всю базу данных целиком.

9.2. Форматы

  • Данные журналов и справочников: CSV, XML.
  • Шаблоны: обычно JSON.
  • База: файл SQLite целиком.

9.3. Практический совет

Если не уверены в формате импорта, сначала выгрузите один реальный объект из системы, откройте файл и используйте его как точный образец для загрузки обратно.

10. Готовые примеры проектирования

10.1. Пример справочника «Номенклатура»

name            text       Название
part_number     text       Номенклатурный номер, unique
unit            directory  Ссылка на справочник единиц измерения
category        directory  Ссылка на категории
barcode         qr         Штрихкод, auto_generate
weight          number     Вес
description     text       Описание

10.2. Пример журнала «Поступление на склад»

doc_number      text
doc_date        date
nomenclature    directory
quantity        number
supplier        directory
price           number
sum_total       calc       price * quantity

10.3. Пример журнала «Выдача со склада»

issue_date      date
nomenclature    directory
quantity        number
target_shop     directory
stock_left      sql

Логика поля stock_left: получить остаток по выбранной номенклатуре как поступление минус уже выданное количество.

10.4. Пример скрытых полей

source_type     hidden      warehouse
operation_code  hidden      ISSUE

10.5. Пример формулы в справочнике

width           number
height          number
area            calc       width * height

11. Частые вопросы

Почему пользователь не видит журнал?

Проверьте подразделение пользователя, его роль, персональные доступы к журналам и принадлежность журнала к доступным подразделениям.

Почему не сохраняется запись справочника?

Обычно причина одна из трёх: не заполнено обязательное поле, нарушена уникальность, или связанный справочник содержит некорректное значение.

Почему в журнале не находится объект по QR?

Убедитесь, что в связанном справочнике есть поле типа qr и в записи реально сохранён код.

Почему нельзя отредактировать шаблон?

Если журнал уже содержит записи или справочник уже заполнен значениями, шаблон специально блокируется, чтобы структура не разошлась с существующими данными.

Почему в экспорте справочника появились дополнительные поля с суффиксом _display?

Это сделано специально для удобства. Основное поле хранит системное значение ссылки, а поле _display показывает человеку, что именно было выбрано в связанном справочнике.

12. Чек-листы

Чек-лист по созданию шаблона справочника

  • Название понятное и короткое.
  • Код шаблона системный и логичный.
  • Первое текстовое поле выбрано как главное отображаемое.
  • У обязательных полей стоит галочка.
  • У действительно уникальных полей включена уникальность.
  • Связанные справочники уже существуют.
  • Формулы проверены на тестовых данных.

Чек-лист по созданию шаблона журнала

  • Все нужные справочники уже сделаны.
  • Для поля типа справочник выбрано отображаемое поле.
  • Фильтр включён только там, где он нужен пользователю.
  • Вкладки формы продуманы и не перегружают экран.
  • SQL-поля протестированы на реальных данных.
  • Скрытые поля имеют правильные значения по умолчанию.

Чек-лист по созданию отчёта

  • Понятно, кто и зачем его будет запускать.
  • Поля параметров названы человеческим языком.
  • SQL возвращает только нужные колонки.
  • Проверены пустые результаты и большие выборки.
  • Настроены права доступа к отчёту.
